# 대학생 참여 프로그램 통합 플랫폼 개발계획서

## 1. 프로젝트 개요

| 항목 | 내용 |
|---|---|
| 프로젝트명 | 대학생 참여 프로그램 통합 플랫폼 (가칭) |
| 한 줄 소개 | 흩어진 정부·공공 프로그램(창업·공모전·청년정책 등)을 한곳에 모아, 내가 지원 가능한 것만 골라 보여주는 웹 서비스 |
| 대상 사용자 | 캡스톤, 공모전, 창업, 대외활동 참여를 원하는 대학생 |
| 핵심 기술 | 공공 API 수집 파이프라인, 데이터 정규화, RAG 기반 질의응답 |

## 2. 추진 배경

- 대학생 대상 프로그램 정보가 K-Startup, 온통청년, 기업마당, 기관별 홈페이지 등에 분산되어 있음
- 기존 공모전 사이트는 단순 목록 나열 위주로, 자격요건(학년, 전공, 지역, 팀 구성 등)을 사용자 조건과 대조해주지 않음
- 공고 본문과 첨부 PDF가 길어 자격요건과 제출서류를 파악하는 데 시간이 많이 듦

## 3. 목표

1. 3개 이상의 공공 데이터 소스를 정기 수집하여 단일 스키마로 통합
2. 사용자 프로필 기반으로 지원 가능한 프로그램만 필터링
3. 공고 원문 기반 RAG로 자격요건·제출서류·일정 질의에 출처와 함께 답변
4. 마감 일정을 캘린더와 알림으로 제공

## 4. 데이터 소스

### 4.1 주요 소스 (정기 수집)

| 소스 | 제공처 | 발급 경로 | 주요 내용 | 비고 |
|---|---|---|---|---|
| K-Startup 조회서비스 | 창업진흥원 | 공공데이터포털 (15125364) | 사업소개, 사업공고, 콘텐츠 | 자동승인, 무료, 개발계정 일 10,000건 |
| 온통청년 청년정책 API | 한국고용정보원 | 공공데이터포털 (15143273) 등록, 키 발급은 온통청년 사이트 | 청년정책명, 정책 분류, 주관기관, 지역코드 | LINK 유형, 무료 |
| 기업마당 지원사업정보 API | 중소벤처기업부 산하 | 기업마당(bizinfo.go.kr) 자체 발급 | 공고명, 사업요약, 신청기간, 소관기관, 지원대상, 해시태그, 분야 | 창업 분야 코드로 필터 가능 |

### 4.2 보조 소스

| 소스 | 형태 | 비고 |
|---|---|---|
| 기관별 공모전 목록 (전북교육청, 천안시, 한전KDN, 한국자산관리공사 등) | 파일 데이터 위주 (CSV) | 갱신 주기가 연간 수준이라 보조 적재용 |
| 사용자 제보 / 관리자 등록 | 내부 입력 | 공개 API가 없는 민간 공모전 보완 |

### 4.3 제약 사항

- 공공데이터포털에는 전국 단위 공모전·대외활동 통합 API가 없음
- 민간 공모전 사이트(씽굿, 링커리어 등)는 공개 API가 없고 크롤링은 이용약관 문제로 제외
- 각 API의 실제 응답 필드는 활용신청 후 명세서로 재확인 필요

## 5. 주요 기능

### 5.1 통합 목록 및 필터
- 유형(창업, 공모전, 청년정책, 교육·일경험), 지역, 마감일, 주관기관 기준 필터
- 마감 임박 순, 최신 등록 순 정렬

### 5.2 프로필 기반 맞춤 추천
- 학년, 전공, 지역, 관심 분야, 팀 여부 입력
- 구조화된 자격요건과 대조하여 "지원 가능 / 확인 필요 / 불가"로 분류

### 5.3 RAG 질의응답
- 예시 질의: "AI 전공 2학년이 이번 달 지원할 수 있는 창업 프로그램 알려줘"
- 공고 원문 근거 문단과 원문 링크를 함께 제시

### 5.4 마감 캘린더 및 알림
- 관심 프로그램 저장, 캘린더 뷰
- 마감 D-7, D-1 알림 (이메일 또는 웹 푸시)

### 5.5 공고 요약 카드
- LLM으로 공고별 핵심 요약(대상, 지원내용, 신청기간, 제출서류) 생성 후 캐싱

## 6. 시스템 아키텍처

```
[공공 API / 파일 데이터]
        |
        v
[수집 스케줄러] -- 일 1회 증분 수집
        |
        v
[정규화 모듈] -- 소스별 필드 매핑, 중복 제거
        |
        v
[구조화 모듈] -- LLM으로 자격요건 추출 (학년, 지역, 전공 등)
        |
        +----------------------+
        v                      v
[관계형 DB]              [벡터 DB]
 프로그램 메타데이터        공고 본문/첨부 청크 임베딩
        |                      |
        +----------+-----------+
                   v
             [백엔드 API]
   목록/필터, 추천, RAG 질의, 알림
                   |
                   v
             [웹 프론트엔드]
```

## 7. 데이터 설계

### 7.1 통합 프로그램 스키마

| 필드 | 타입 | 설명 |
|---|---|---|
| id | string | 내부 고유 ID |
| source | enum | KSTARTUP, YOUTH_CENTER, BIZINFO, FILE, USER |
| source_id | string | 원본 고유 ID (중복 판별용) |
| title | string | 프로그램명 |
| type | enum | STARTUP, CONTEST, POLICY, EDUCATION |
| summary | text | 사업 요약 |
| host_org | string | 주관/소관 기관 |
| target_text | text | 원문 지원대상 |
| eligibility | json | 구조화된 자격요건 (학년, 지역, 전공, 연령, 팀 여부) |
| region | string | 대상 지역 |
| apply_start | date | 신청 시작일 |
| apply_end | date | 신청 마감일 |
| url | string | 원문 링크 |
| attachments | json | 첨부파일 목록 |
| updated_at | datetime | 마지막 수집 시각 |

### 7.2 기타 테이블
- users: 프로필(학년, 전공, 지역, 관심 분야)
- bookmarks: 사용자별 관심 프로그램
- notifications: 알림 예약 및 발송 이력

## 8. RAG 설계

| 단계 | 방식 |
|---|---|
| 문서 수집 | 공고 본문 + 첨부 PDF 텍스트 추출 |
| 청킹 | 공고 섹션(지원대상, 지원내용, 신청방법, 제출서류) 단위 우선, 길면 토큰 기준 분할 |
| 메타데이터 | program_id, type, region, apply_end, 섹션명 |
| 검색 | 메타데이터 사전 필터(마감 전, 지역) + 벡터 검색 + 키워드(BM25) 하이브리드 |
| 생성 | 검색 청크 기반 답변, 근거 문단과 원문 링크 인용 필수 |
| 평가 | 질의 30~50개 테스트셋으로 검색 적중률, 근거 일치율 측정 |

## 13. 진행 현황

> 2026-11-10 기준. ✅ 완료 · 🟡 일부 완료 · ⬜ 안 함

### 13.0 계획 대비 바뀐 구조

- **DB·인증은 Supabase 사용**: PostgreSQL + pgvector + Auth(auth.users)를 Supabase로 대체
- **프론트가 Supabase에 직접 접속**: 목록 조회, 로그인, 프로필·북마크 저장은 anon 키 + RLS 정책으로 처리 → 이 기능들은 FastAPI 없이 동작
- **FastAPI는 비밀 키가 필요한 기능만 담당 예정**: LLM 자격요건 추출, RAG 질의응답, 알림 발송
- **수집 스케줄러는 GitHub Actions**: APScheduler/Celery 대신 `.github/workflows/collect.yml` (매일 06:00 KST, 수동 실행 가능)
